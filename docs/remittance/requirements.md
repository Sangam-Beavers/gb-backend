# 송금 · 환전 · 충전 (주머니) — 요구사항 (Requirements)

> 도메인 prefix: `/wallets`, `/transfers`, `/exchanges`, `/accounts`
> 사용 뷰: 2. 메인 / 3. 송금 / 4. 환전 / 5. 충전
> 정본 명세: [`api-spec.md`](./api-spec.md) · 공통 규칙: [`../conventions.md`](../conventions.md)

---

## 1. 범위

앱의 핵심 금융 기능. **주머니(전자지갑)** 를 중심으로 4개 흐름을 담당한다.

- **메인** — 주머니 잔액, 원화 환산, 환율
- **충전(가져오기)** — 타행 계좌 → 주머니 포인트
- **송금(보내기)** — 앱 사용자 송금 / 타행 송금 / 정기 송금
- **환전** — 원화↔외화 (환전/재환전)

> **구현 수준 2 (Mock API):** 실제 PG/은행 대신 가상 은행(Beaver/Quokka Bank) Mock으로 처리. 인터페이스는 실서비스와 동일하게 설계.

---

## 2. 주머니(전자지갑) 기본

- 사용자당 주머니 1개. 통화별 잔액(`KRW`/`USD`/`PHP`/`VND`)을 보유.
- **메인 통화** 지정 가능(기본 KRW). 메인 화면에서 메인 통화가 가장 위, 나머지는 아래에 작게 표시.
- **"지금 나의 원화"** — 전체 보유 통화를 원화로 환산한 합계를 한 칸에 표시.
- 잔액은 **절대 캐싱 금지.** 항상 DB 직접 조회.

---

## 3. 충전 (가져오기)

타행 계좌의 돈을 주머니 포인트로 충전. **계좌 등록 → 충전** 2단계.

### 계좌 등록 프로세스
1. '가져오기' → 등록된 내 계좌 목록 + '계좌 추가'
2. 계좌 추가 시: 은행 선택 → 계좌번호 입력 → 예금주 실명 조회
3. 계좌 연결 및 **자동이체 인증 요청** → Mock 은행 `verify`로 `account_token` 발급 (※ 실제 인증은 구현 불가 → 화면/Mock만)
4. 계좌 등록 최종 완료 → `bank_accounts` 등록 (받은 토큰을 `mock_account_token`에 저장 → 충전 시 사용)

### 충전 프로세스
1. 출금할 등록 계좌 선택
2. 충전 금액 입력
3. 충전 실행 → 주머니 포인트 +P (통화 KRW 고정)

## 4. 송금 (보내기)

두 가지 방식 + 정기 송금.

### 앱 사용자 송금 (`INTERNAL_TRANSFER`)
- 수령인 이메일(아이디)로 검색/선택 → 금액 입력 → 송금. **수수료 무료.**

### 타행 송금 (`REMITTANCE`)
- 은행 선택 → 계좌번호 입력 → 예금주 실명 조회 → 금액·통화 입력 → 수수료/환율 확인 → 송금. **수수료 발생.**

### 송금 공통 흐름 (사전 단계가 별도 API)
```
수수료 조회 → (송금 비밀번호 검증) → 송금 실행
```
- 송금 실행은 **`POST /api/v1/transfers` 1단계 즉시 실행** (PENDING 후 별도 execute 없음).
- **멱등성 키 헤더** + Redis 분산 락으로 이중 송금 방지.
- 한 트랜잭션에서: 수수료·수취금액 계산 → 잔액 검증 → 차감 → audit log 기록.

### 정기 송금
- 대상 유효성 검증 → 지원 통화 조회 → 정기 송금 설정 → 내역/진행 완료 조회.

---

## 5. 환전

- **환전(`EXCHANGE`)**: 원화 → 외화 (USD/PHP/VND)
- **재환전(`RE_EXCHANGE`)**: 외화 → 원화
- **2단계: 견적 → 실행.** 견적(`quote`)은 실시간 환율·예상 수령액·만료 시각 반환. 실행은 견적 식별자(`quote_public_id`)로.
- 송금 시에는 어떤 통화로든 보낼 수 있음(보유 통화 기준).

---

## 6. 메인 화면 부가 기능

- **실시간 환율 조회** — 여러 나라 환율, 슬라이드, 전체 보기.

---

## 7. 비기능 / 무결성 요구

- 금액·환율은 모두 `string` 십진수 송수신, 서버는 `BigDecimal`.
- 미인증 사용자는 충전/송금/환전 불가(인증 배지 필요).
- 잔액 변경은 `@Transactional` 안에서 [잔액 조회 → 검증 → 업데이트 → 감사 로그 INSERT → 커밋] 순서 보장.
- 감사 로그(`transaction_audit_logs`)는 append-only.
